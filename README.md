# ta2debug

macOS 向けの TUI デバッガ（lldb 風の操作感）。`task_for_pid()` でタスクポートを取り、
Mach 例外ポートを差し替えて例外を受け取る。**対象プロセスはアタッチ後も動き続ける**（non-stop）。
設計の詳細は [`DESIGN.md`](DESIGN.md)。本書は「何ができて、どう使うか」をまとめた利用者向けの入口。

> このツールは **AI からも使われることを想定**している。ソースを読まなくても機能が分かるよう、
> コマンドだけでなく「停止時に自動で出る解析」も本書に明記する（→ [自動解析機能](#自動解析機能自動で出る操作不要)）。

---

## 大前提（他のすべてに優先する 2 点）

- **A. アーキテクチャ移植性**: 現在 x86_64 のみだが、いずれ Apple シリコン（arm64）に対応する。
  アーキ依存はすべて `Arch` 抽象の裏に隔離してある（レジスタ名・命令バイト・ステップ方式など）。
  arm64 実装はコンパイル・構文確認済みだが、**実機検証は未**（HW ブレイク本数・arm64e の PAC strip 等は実機要確認）。
- **B. 依存最小**: 外部ライブラリは **capstone 1 つだけ**（x86_64/arm64 両対応なので arm64 化でも増えない）。
  md5/sha1 はシステムの CommonCrypto、JSON は同梱の picojson（ヘッダ 1 つ）。それ以外はシステムフレームワーク / libSystem のみ。

## セキュリティ上の制約（重要）

**扱う対象は自分でビルドしたプログラムに限る。** システムプロセスや、
DRM / コピープロテクト等の**保護を回避する目的の対象は扱わない**。この制約はツールの設計方針であり、逸脱しない。

実行には SIP 無効環境・root 権限が必要（`task_for_pid()` と Mach 例外ポートの差し替えのため）。

## ビルド

```sh
# 依存: capstone（brew install capstone）
cmake -G Ninja -S . -B build
ninja -C build
```

生成物: `build/ta2debug`（本体）と各 `*_selftest`（arch / target / break / symbols の単体テスト）。
arm64 クロス確認は `clang++ -std=c++17 -arch arm64 -Iinc -fsyntax-only <file>` で構文チェックする。

## 起動

```sh
sudo ./build/ta2debug                 # 空で起動 → :attach / :run
sudo ./build/ta2debug <pid>           # 引数が全数字 → その pid に attach
sudo ./build/ta2debug <path> [args…]  # それ以外 → バイナリを起動してデバッグ（エントリ手前で停止）
```

TUI（全画面・raw モード）。`:help` でいつでもコマンド一覧を表示。`:q` で終了。

> **起動時に IME を半角へ切り替える**（Carbon の TIS で ASCII 可能なキーボードレイアウトを選択）。
> 日本語入力モードのまま起動してもコマンドが全角にならないようにするため。**切り替えは起動時の一度だけ**で
> 固定はしないので、以降は全角へ自由に戻せる（例: `:memo` に日本語を書くときは IME を日本語へ戻してよい）。
> GUI 入力ソースが無い環境では何も起きない（best-effort）。

> **launch した対象は ASLR を無効化**して起動する（`posix_spawn` に `_POSIX_SPAWN_DISABLE_ASLR`。lldb/debugserver の既定と同じ）。
> dyld スライドが 0 に固定され、**再実行のたびに同じアドレス**になる（ブレイクのアドレス指定やログ突合が再現可能）。
> これが効くのは launch 時だけで、既に動いているプロセスへの `attach` は対象のレイアウトのまま。

## 非対話（バッチ）モード — AI / スクリプト向け

TUI に入らず、コマンド列をそのまま流して**プレーンテキストの応答を stdout に得る**。lldb の `-b -o` 相当。
AI からはこれが一番扱いやすい（画面スクレイプ不要・結果がそのまま読める）。

```sh
sudo ./build/ta2debug -b <対象> -o "b add" -o "c" -o "where" -o "q"   # -o のコマンドを順に実行
sudo ./build/ta2debug -b <対象> -s commands.txt                      # ファイルの各行を実行（- で標準入力）
printf 'b add\nc\nwhere\nq\n' | sudo ./build/ta2debug -b <対象>       # 標準入力から（-o/-s 無しなら stdin）
```

- `<対象>` は pid（全数字）か 実行ファイルパス[+引数]。省略して `-o "run <path>"` / `-o "attach <pid>"` でもよい。
- `-o` か `-s` があれば `-b` は省略可。コマンドは TUI と同じ綴り（先頭 `:` は付けても付けなくても可）。`#` 始まりはコメント。
- **実行制御コマンド**（TUI ではキー操作だったもの）:
  `c`/`continue`・`s`/`step`/`si`・`n`/`next`・`where`/`backtrace`（バックトレース表示）・`wait`（次の停止まで待つ）。
- 停止すると **位置・ブレイク命中・クラッシュ理由・syscall 注記・バックトレース**を自動で出力する。
- `run` はエントリ停止まで、`c`/`s`/`n`/`auto` は次の停止まで自動で待つ。
  `attach` は対象を走らせたままなので、ブレイク設定後に `wait` で停止を待つ。
- レジスタは式中で `$`（または `%`）を付けて参照。**アーキ非依存の別名 `$pc` / `$sp` / `$fp`**（+ arm64 は `$lr`）が
  両アーキで使えるので、スクリプトはアーキを問わず書ける。アーキ固有名（`$rip`/`$rsp` 等）も可。
  例: `x/8i $pc`（現在位置から 8 命令を逆アセンブル）、`x/4xg $sp`（スタックを 16 進）。

実行例:

```
ta2> run prog
stopped @ prog 0x3ee0  main+0x0
backtrace:
  0x...ee0  prog  main+0x0
  0x...52e  dyld  start+0x1ce  ← スタック走査で復元(推定)
ta2> b add
#1 ブレイク設定 0x...e70  prog 0x3e70  add+0x0
ta2> c
stopped @ prog 0x3e70  add+0x0  [bp #1, 1hit]
backtrace:
  0x...e70  prog  add+0x0
  0x...ec0  prog  calc+0x30  ← [sp] から復元
  0x...f07  prog  main+0x27
  0x...52e  dyld  start+0x1ce
```

## コマンド一覧

式には **16進(0x..) / 10進・シンボル名・レジスタ名・`main+0x10` のような加減算**が使える。

**シンボル名はライブラリ名を省略できる**：既定ライブラリ（`:uselib`）→ 主実行ファイル → **ロード済み全ライブラリ**の順に探す
（例: `:b usleep` でライブラリ指定なしに解決）。複数ライブラリに別アドレスで存在する場合は、該当ライブラリを挙げて
`ライブラリ名!シンボル`（例 `libsystem_malloc!malloc`）での明示を促す。明示指定はいつでも使える。

バイナリの隣に **dSYM（`<バイナリ>.dSYM/…`）があり UUID が一致すれば、その symtab も読み込む**ので、
**strip 済みバイナリでも関数名が出る**（thin / fat 両対応）。

dSYM に **DWARF 行情報（`.debug_line`）があれば、ソース行を表示**する（自前パーサ、DWARF v2–4 対応）：
- 逆アセンブル画面に、該当する **`ファイル:行  ソーステキスト`** を淡色で挿入（lldb 風）。
- バッチの停止レポートに `src: <ファイル>:<行>  <ソース>` を出力。
- `comp_dir` を `.debug_info` から取り、ソースファイルを読んで実際の行テキストも表示（見つかる場合）。
- dSYM 生成は `clang -g -c` で `.o` を残してから `dsymutil`（単一ステップの `clang -g` は `.o` が消え行情報が入らないことがある）。DWARF v5 は未対応（行表示なしに劣化）。

アタッチ／起動時に**全ライブラリのシンボル一覧をバックグラウンドで先読みし、`~/Library/Caches/ta2debug/syms/` に UUID 別名で保存**する。
ライブラリが更新されると UUID が変わるので自動的に新しいキャッシュを作る（古いものは参照されない）。2 回目以降の起動は読み込みが速い。
**先読み中はヘッダに「⏳シンボル先読み N/M」と進捗を表示**し、終われば消える（固まって見えないように）。先読みは別スレッドなので操作はブロックしない。

### システムコール監視（libdtrace・止めずに観測）
| コマンド | 説明 |
|----------|------|
| `:scwatch <名前\|all>` | **BSD syscall** を**カーネル計測（libdtrace）で監視開始**（例 `:scwatch write` / `:scwatch all`） |
| `:scwatch mach[:<名前>]` | **Mach トラップ**を監視（例 `:scwatch mach` / `:scwatch mach:mach_msg_trap`）。集計表示は `mach:` を前置 |
| `:scwatch` | 監視状況（名前ごとの回数・総計）を表示 |
| `:scwatch off` | 監視停止 |

BSD システムコール（`syscall` プロバイダ）と Mach トラップ（`mach_trap` プロバイダ）は別物なので、
`mach` 系で明示的に切り替える。Mach トラップは `mach:mach_msg_trap` のように `mach:` 付きで集計表示され、BSD と区別できる。
（`EXC_BAD_ACCESS` 等の **Mach 例外**は syscall でもトラップでもなく、ta2debug 自身の例外検知で停止・表示する別経路。）

ユーザ空間のブレイク／単一ステップではなく、**カーネルのシステムコール・ディスパッチ表計測**に相乗りするので、
**全 syscall を単一ステップ無しで低コストに捕捉**できる（`:auto syscall` の単一ステップ方式とは別物）。
対象は**止めずに**観測し、syscall 名ごとの回数を集計表示する（全件だと秒間数千になり得るため逐次表示ではなく集計）。
`libdtrace`（システムライブラリ）を使うため SIP 無効＋root が必要（ta2debug の前提と同じ）。

### システムコール停止キャッチポイント（libdtrace・発火で止める）
| コマンド | 説明 |
|----------|------|
| `:scstop <名前\|all>` | その **BSD syscall** 発火で対象を停止（例 `:scstop write` / `:scstop all`） |
| `:scstop mach[:<名前>]` | その **Mach トラップ**発火で停止（例 `:scstop mach` / `:scstop mach:mach_msg_trap`） |
| `:scstop` | 停止キャッチポイントの状況（対象フィルタ・命中回数）を表示 |
| `:scstop off` | 解除 |

フィルタ書式は `:scwatch` と同じ（`all` 省略可・`mach:` で Mach トラップ）。マッチした syscall/トラップが
発火した**瞬間に**、dtrace の破壊的アクション `stop()` が**カーネル内で同期的に対象タスクを凍結**する。
ta2debug はこれを**通常のブレイク停止と同じ**ように扱い、停止理由「`syscall キャッチ: <名前>`」とともに停止する
— レジスタ・メモリ・**正確なバックトレース**（`write ← main ← …` のように呼び出し元まで）を検査でき、`c` で
**次の発火まで**走る（キャッチポイントは自動で再武装）。単一ステップではなくカーネル計測なので、**到達点が精密**
（まさにその syscall を呼ぶ地点で止まる）かつ低コスト。

- `stop()` はカーネルが `task` レベルで suspend するので、再開は ta2debug が `task_resume` で行う（デバッガ終了・
  `:scstop off` 後の `c` でも確実に解除される）。
- `:scwatch`（観測）と `:scstop`（停止）は**同じ dtrace ハンドルを共用するため排他**。一方を設定するともう一方は解除される。
- `EXC_BAD_ACCESS` 等の **Mach 例外**は syscall でもトラップでもなく、ta2debug 自身の例外検知で停止する別経路（上記とは無関係）。
- 複数スレッド対象では、停止時に表示するスレッドが発火したスレッドと一致しない場合がある（単一スレッド対象では一致）。

## 自動解析機能（自動で出る・操作不要）

コマンドではなく、**停止するたびに自動で表示される**解析。AI が結果をそのまま信用してよい精度の裏づけ：

- **CFI 正確バックトレース** — compact unwind（`__TEXT,__unwind_info`）と DWARF（`__TEXT,__eh_frame`）を
  解釈してフレームを復元する。frame-pointer に頼らないので **-O2 の frameless 関数でも正確**。
  さらに **関数入口直後 / IP=0 / stub 経由**でも、戻りアドレスを `[sp]`(x86) / `LR`(arm64) から復元して呼び元を失わない。
  compact unwind で解決できなければ fp チェーン→スタックスキャンへ段階的にフォールバックする。
- **syscall 事前解析** — 停止位置が `syscall`/`svc` 命令なら、これから呼ぶシステムコールを引数ごと解読して
  `→ syscall: write(1, 0x.., 14) "hi"` のように表示。ポインタ引数は参照先（C 文字列・バッファ）も展開し、
  フラグは記号化する（`O_*`, `PROT_*`, `MAP_*`, `R_OK/W_OK/X_OK`, `SEEK_*`, シグナル名 等）。
  **Mach トラップ**も名前・引数・ポート権利で分解し、`mach_msg` は `msgh_bits` とディスクリプタ（port/ool/ool_ports）まで展開。
- **スタブ解決** — PLT 相当の `__stubs` を間接シンボルテーブル経由で解決し、`symbol stub for: X` と表示。
  stub がすぐ `jmp` する場合でも呼び元の表示を保つ。
- **デマングル + テンプレート省略** — C++ シンボルを Itanium デマングルし（内部リンケージの `_ZL…` も対応）、
  `std::__1::`→`std::` に畳み、長いテンプレート引数群を `std::map<…>` のように省略表示する。
- **例外（クラッシュ）検知** — 不正メモリ参照・不正命令・算術例外で対象が落ちると自動停止し `⚠` と理由を表示。
  停止後にレジスタ/メモリ/バックトレースを確認でき、`c` でシグナルを本来のハンドラへ通して通常終了させられる。

## ユーザ注釈（自分で付ける名前・メモ）

シンボルが無い（strip 済みの）**自作バイナリ**に、**自分でアドレスに名前やメモを付けられる**。
付けた名前はそのまま**シンボルとして振る舞う**ので、以降は `:b <名前>` でブレイクでき、`:sym` や式でも引け、
停止表示・バックトレース・逆アセンブルにも出る。メモは停止表示などに ` ; メモ` の形で添えられる。
dSYM が無い／strip 済みで関数名が出ない対象を、解析しながら少しずつ「読める」状態にしていくための機能。

> **用途は自分でビルドしたプログラムに限る**（→ [セキュリティ上の制約](#セキュリティ上の制約重要)）。
> 第三者バイナリや保護対象にシンボルを後付けする手段ではない。既存のシンボル表は一切書き換えず、
> **上に重ねるだけ**なので、注釈を消せば元の挙動に完全に戻る。

### 使い方の例

```
:ann helper,Triple,x*3+1 を計算      # アドレス（式）に名前＋メモを付ける
:ann 0x100003f50,parseHeader          # 生アドレスに名前だけ
:memo $pc,ここで NULL 参照して落ちる  # 今の PC にメモだけ（名前は付けない）
:b Triple                             # 付けた名前でブレイク
:sym Triple                           # 0x…  prog 0x…  Triple+0x0  ; x*3+1 を計算
:anns                                 # 主実行ファイルの注釈一覧（保存先パスも表示）
:unann Triple                         # 削除（`:memo Triple,` でメモだけ消すのも可）
```

`<式>` にはアドレス・シンボル名・`main+0x10`・レジスタ（`$pc` など）が使える。
名前・メモに `,` を含めたいときは、最初の `,` までが式／次が名前／残り全部がメモ、として解釈される
（メモの中の `,` はそのまま通る）。

### 重ね合わせの規則

- **名前の重複アドレス**: 注釈と実シンボルが同じアドレスにあると、**注釈の名前が優先**して表示される
  （strip 済み関数に自分の名前を付けられる）。
- **メモだけの注釈**（名前なし）: 実シンボル名は残したまま、メモだけを添える。
- **名前で引けないとき**: 同じ名前が別アドレスに複数あると、式解決は「複数あります」と候補（名前＠アドレス）を挙げる。
  アドレスか `ライブラリ名!名前` で明示する。

### ファイル形式（手で編集できる）

注釈は**イメージの UUID ごと**に、プレーンな**タブ区切りテキスト**で保存される。普通のエディタで直接編集してよい。

```
# ta2debug annotations v1  (手編集できます / editable by hand)
# 形式: <16進アドレス(unslid)> <TAB> <名前> <TAB> <メモ>
# uuid=C8818C7F86423FC3B7A598A9D3A6186D
# path=/path/to/your/binary

0x100003f30	Triple	x*3+1 を計算
0x100003f40	MyMain	プログラム入口
0x100003f50		ここはメモだけ
```

- **保存先**: `~/Library/Application Support/ta2debug/annotations/<UUID>.t2a`
  （更新されやすいキャッシュとは別の「消さないユーザデータ」の場所。UUID 別なのでバイナリを作り直すと自動的に別ファイル）。
- **アドレスは unslid（slide を抜いた静的アドレス＝Mach-O 上の vmaddr）**で持つので、**再実行や ASLR を跨いでも有効**。
  `:anns` は実行時アドレスと unslid の両方を表示する。
- 手編集はおおらかに読む: `0x` の無い生 16 進も可、`#` で始まる行はコメント、空行は無視、同じアドレスが重複したら後勝ち。
  ただし**デバッガが書き直すと、名前とメモは残るが自由記述の `#` コメント行は消える**（構造化データだけを再生成するため）。

### 起動中でも自動で読み直す

デバッガの**各コマンド実行時**と**停止するたび**に、注釈ファイルの更新（mtime とサイズ）を見て、
変わっていれば**自動的に読み直す**。デバッガを起動したまま別のエディタでファイルを編集すれば、次の操作から反映される。

### sudo と所有権

本ツールは root（`sudo`）で動かすため、デバッガが書いた注釈ファイルは本来 root 所有になる。
手編集をしやすいよう、**`sudo` 実行時は呼び出しユーザ（`SUDO_UID`）へ所有権を戻す**ので、root なしでそのまま編集できる。

## 既知の制約

- **arm64 は実機未検証**（構文・クロスコンパイルのみ）。LR アンワインド・arm64 Mach クラス判定・
  HW ブレイク/ウォッチ本数・arm64e の PAC strip は実機で要確認。
- SIP 無効 + root 前提。
- x86 では `$sp` を**完全な 64bit スタックポインタ**（=`$rsp`）として扱う（伝統の 16bit sp よりクロスアーキ一貫性を優先）。
  16/32bit が要るときは `spl`/`esp`/`rsp` を使う。

詳しい設計判断・層構成・アーキ抽象の内訳は [`DESIGN.md`](DESIGN.md) を参照。
